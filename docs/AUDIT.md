## 风险与建设结论

没有目标场景可测，因此不能虚构改造前的城市 FPS、泄漏或 draw call。借鉴已有工程的模块方式，新建独立 `coastal-city` Vite/TypeScript 应用，以真实程序化城市替代外网资源依赖。

1. **渲染/场景管理**：单 renderer、单 RAF、单时间源；统一 resize、可见性暂停、context loss 和 teardown。
2. **摄像机**：复用 OrbitControls 的阻尼、触摸；补充平滑定位、键盘飞行、区域/俯瞰/海岸/街道机位；避免键盘抢占输入控件。
3. **资源加载**：目标场景暂无外部模型。不请求 CDN，不引入未授权模型。共享几何/材质与程序纹理；明确初始化失败和恢复路径。
4. **交互**：真实 raycast 到实例建筑 ID；拖动不触发选择；DOM 选楼列表和可点击小地图提供触摸/键盘替代入口。
5. **性能**：建筑、窗光、树木、道路装饰、车辆和行人按实例批处理；天气使用单个预分配粒子缓冲区；阴影只在灯光/设置更新时重算；避免每帧写 DOM/生成对象。
6. **释放**：几何/材质/纹理按 Set 去重；实例、灯光阴影、事件、订阅、observer、RAF 都释放；销毁可重复调用。
7. **模拟真实性边界**：确定性合成城市与遥测，不宣称接入真实 GIS、传感器或真实交通数据。时间、天气、事件必须影响实际场景与指标。

## 实施优先级

P0：严格 TS、基础入口、确定性城市数据、资源所有权、时钟/状态模型、可运行 3D。

P1：差异化海岸/商务/住宅/生态布局、实例建筑与道路、天空/水体/植被；建筑选择/详情/搜索、相机、小地图；时间/天气/交通/行人/事件。

P2：画质档、性能采样、隐藏页暂停、恢复/异常处理、手机布局；单测、生产构建、实际浏览器自动验收、性能与稳定性记录。

P3：操作手册、架构和验证报告；明确测量设备及限制。

## 验收标准

- `npm run typecheck`、`npm test`、`npm run build` 全部通过；根现有 41 个测试继续通过。
- 生产页面在本机 Chrome 实际创建 WebGL 场景，无页面异常或 shader 错误。
- 可点击建筑并显示匹配资料；搜索、区域切换、小地图、相机预设、键盘操作、清除选择、暂停/继续、时间速率、昼夜、晴雨雪、画质均产生可验证状态/画面变化。
- 暂停冻结时钟、车辆和行人；真实帧时差限幅，后台恢复不跳时；极端输入不会产生 NaN 或越界。
- 固定 seed 的建筑不侵占道路、广场、海域，至少四个空间片区，建筑 ID 唯一。
- 预设场景 draw calls 目标小于 180（含阴影）；桌面默认三角形目标小于 250k；采样报告实际值，不把软件 WebGL 的 FPS 当硬件承诺。
- 多次天气/区域/画质切换后 GPU 几何/纹理数量稳定；销毁/恢复后无重复 canvas 或动画循环。
- 390px 手机界面无横向溢出，主要控制可操作；WebGL 不可用或丢失时提供明确可恢复提示。
