## 性能

雨天从均衡切到流畅，采样峰值三角面降约 60%，绘制调用降约 42%，帧缓冲像素降约 47%。流畅档关闭并释放阴影贴图、简化水面着色，降低装饰、密度及渲染分辨率。均衡和精细档用 1280/2048 阴影贴图，按光位阈值更新。

软件回退同机实测：均衡晴 11.0 FPS，均衡雨 10.8 FPS，流畅雨 23.5 FPS，精细雨 7.5 FPS。软件渲染在低帧率下会因步长限幅而让模拟进度落后墙钟。硬件路径首个 3D 可用标记 612 ms，软件路径 678 ms（单次本地生产页面加载，包含 JavaScript、世界生成和首帧；不推断网络或其他设备上的加载时间）。

开发中首个全域均衡晴天采样使用逐窗几何：常规帧 56 次调用、81,728 三角面，原场景 69 个 Mesh、19,020 个网格/实例条目。改用带占用遮罩的合并立面纹理、实例化远景并调整机位和景观后，常规帧为 50 次调用、59,048 三角面，50 个 Mesh、4,112 个条目。两个版本均为同视口的全域机位，最终机位及部分景观略有调整；这组数据是版本对照，不能将差值单独归因于某个优化。

三轮区域、画质和天气交替后，同一视角的几何/纹理为 28/7 → 28/7；上下文恢复会按当前视角重新上传必要几何。75.001 秒 60× 测试绘制 4,495 帧，进入第 4 模拟日，覆盖全部天气和三种事件。300 次状态采样中，首循环预热之后几何计数保持 27，纹理峰值 7；画布始终 1 个。此结果说明所测路径上未观察到资源计数增长，不等同于跨设备或长时间内存证明。

## 已发现并修复

- 初始建筑随机宽深可能侵入道路退界。按地块中实际位置限制外轮廓，给人行道、基座和屋檐保留间距，增加几何回归用例。
- 小地图坐标验收曾要求比单个地图像素更高的精度。按 SVG `getScreenCTM` 映射真实点击，以一像素对应的米数设定验收精度；标记和指北针共享正确方向。
- 大量逐窗面和不必要的全屏着色影响软渲染。改成共享窗面纹理，先写不透明物体深度，再画水和天，释放流畅档阴影资源。
- 暂停时原型仍在轮询帧。离开交互后停止 RAF，由输入、状态变化或可见性唤醒；按相同事件等待场景提交后才断言演员和 GPU 数据。
- Windows 系统临时文件清理令单体 Three.js 构建失败。拆分 Three 核心和 WebGL 模块后构建通过；另换本机空闲端口 4246/4247。
- 禁用 WebGL 时验收中的状态曾依赖未创建的渲染器。根状态独立于渲染器，页面可展示回退及建筑检索；恢复或重建不复制监听和画布。

## 范围与后续

三维、天气与遥测为合成情景，尚未接入真实 GIS/BIM、传感器或天气源。车辆和行人用街区环路径与启发式流量，无路口仿真、跨区寻路、动态障碍或碰撞物理。1.0 没有服务端存储、情景分享与回放。手机只测 Chromium 仿真，Safari、真机和不同 GPU/长时间内存仍需验证。
